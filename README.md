# Sandy Voyage / 모래 세계 일주

Godot 4.7 (GDScript) 프로토타입. Android 우선, 세로 720×1280.

## 직접 플레이하기 (Godot 편집기)

1. Godot 4.7.2로 이 폴더(`project.godot`)를 엽니다.
   이미 열려 있었다면 **프로젝트 → 현재 프로젝트 다시 불러오기**를 한 번 실행하세요.
   편집기가 새로 추가된 스크립트 클래스를 인식해야 오류 표시가 사라집니다.
2. **F5**(프로젝트 실행)를 누르면 홈 화면이 열립니다. 메인 씬은 `scenes/main.tscn`입니다.
   `main.tscn`을 열어 둔 상태라면 **F6**(현재 씬 실행)으로도 같은 화면이 뜹니다.
3. 처음에는 **여행 시작하기**를 누르면 하와이 1부터 시작합니다. 세계 지도 → 대륙 → 여행지를 눌러 고를 수도 있습니다.

PC 창이 화면보다 크면 창 크기를 줄여도 됩니다. 화면은 비율을 유지한 채 맞춰집니다.

### 조작법

| 동작 | 방법 |
|---|---|
| 블록 이동 | 블록을 누른 채 위·아래·왼쪽·오른쪽으로 드래그합니다. 처음 움직인 방향의 축 하나로만 움직입니다. |
| 놓기 | 손을 떼면 가장 가까운 칸에 맞춰집니다. 반 칸이 안 되게 움직이면 제자리로 돌아갑니다. |
| 막힘 | 벽, 보드 끝, 다른 블록에 닿으면 그 앞에서 멈춥니다. 블록은 회전하지 않습니다. |
| 모래 수집 | 블록을 **맨 윗줄**(풍경 바로 아래)에 두면, 블록과 같은 색 모래에 닿았을 때 자동으로 수집합니다. |
| 수집 힌트 | 블록을 잡고 있는 동안, 맨 윗줄에서 그 색을 지금 수집할 수 있는 칸이 블록 색으로 표시됩니다. |
| 블록 완료 | 블록이 100%가 되면 사라지고 그 자리가 빈칸이 됩니다. |
| 클리어 | 모래가 하나도 남지 않으면 그 스테이지의 엽서를 얻습니다. 같은 여행지의 **다음 스테이지** 또는 **여행지로 돌아가기**를 고를 수 있습니다. 3장을 모두 모으면 방문 완료 스탬프가 찍힙니다. |
| 하단 버튼 | 여행지(여행지 엽서 화면으로) / 다시 하기 / 설정 |
| 설정 | 소리 켜기·끄기, 모래 해상도 128↔64 비교. 해상도를 바꾸면 현재 스테이지를 처음부터 다시 시작합니다. |

### 수집 규칙 요약

스테이지마다 `data/stages.json`의 `"physics"`와 `"collect"` 값으로 규칙이 정해집니다.

**하와이 1 — 중력 + 범위 제한 연쇄 흡입 B-2 (`"physics": "gravity"`, `"collect": "suction"`)**

거리는 모두 128×128 모래 격자의 **셀(모래 한 알) 단위**입니다(64 해상도에서는 절반으로 환산: 연결 2, 반경 24).

- 블록 수집구 바로 위 셀에 **같은 색 모래가 직접 닿아야** 흡입이 시작됩니다.
- 이미 끌려오는 모래에서 가로·세로 모두 **3셀 이내**(`max(|dx|,|dy|) ≤ 3`)에 있는 같은 색 모래가 연쇄로 함께 끌려옵니다. 사이에 다른 색이 있어도 건너뜁니다.
- 수집구에서 **48셀 이내**(`√(dx²+dy²) ≤ 48`)의 모래만 대상입니다. 범위 밖 모래는 연쇄도 통하지 않습니다.
- 다른 색은 절대 가져가지 않고, 블록의 남은 수용량보다 많이 가져가지 않습니다.
- 수집 여부는 블록을 움직였는지가 아니라 **지금 수집구에 같은 색이 닿아 있는지**로 정해집니다. 맨 윗줄에 놓인 블록은
  매 프레임 자기 수집구 픽셀만 확인하므로, 다른 블록의 수집으로 무너져 내려온 같은 색 모래가 닿으면 움직이지 않아도
  다시 빨아들입니다. 여러 블록이 동시에 각자 수집합니다. 블록을 누르기만 해서는 멈추지 않고, 실제로 끌기 시작한
  순간부터 놓을 때까지만 수집이 멈춥니다(끄는 동안 힌트는 그 블록이 이미 서 있는 칸을 표시하지 않습니다).
- 수집된 모래는 격자에서 실제로 지워지고, 빈자리로 주변 모래가 떨어져 그림이 무너집니다.
- **90% 마무리:** 블록이 수용량의 90%를 채우면, 그 색의 남은 모래를 거리 제한 없이 (남은 수용량만큼) 3배 속도로 빨아들입니다. 블록이 맨 윗줄에 있어야 하며, 끝나면 정확히 100%에서 블록이 사라집니다.
- 연출: 모래 한 알마다 입자 하나가 그 알이 지워진 자리에서 출발해 수집구로 끌려 들어갑니다. 블록의 채움 %와 상단 진행률은 입자가 **도착한 만큼** 오릅니다.
- 설정: `data/game_config.json` → `gravity.suction`(연결 거리, 반경, 90% 기준(0이면 끔), 마무리 속도, 수집 속도, 프레임당 탐색량), `gravity.suction_fx`(입자 속도·시간).
- 모래 대각선 이동: 하와이 1은 기존 방식(아래가 막히면 비어 있는 대각선 아래 칸으로 이동)을 씁니다
  (`stages.json`의 `"diagonal_needs_side_gap": false`). 비교용으로 `true`로 바꾸면 같은 높이의 옆 칸도 비어 있을 때만
  대각선으로 미끄러집니다(색 혼합은 줄지만 붕괴가 굳어 보여 채택하지 않음). 기본값은 `data/game_config.json` →
  `gravity.diagonal_needs_side_gap`(false).
- 붕괴 갱신(하와이 1, `"column_wake": true`): 모래가 수집되면 그 위쪽 열 전체(좌우 이웃 청크 포함)의 시뮬레이션
  청크를 깨워, 위 모래가 한 번에 내려앉습니다. 끄면 위쪽이 8×8 청크 단위로 한 칸씩 깨어나 빈 틈이 가로줄처럼
  천천히 올라가 보입니다. 기본값 `gravity.column_wake`(false).
- 보드: 하와이 1만 **8×4**(다른 스테이지는 8×5)입니다. 시작 시 라군 블록이 맨 윗줄을 막고 있어, 야자수 블록은
  혼자서는 수집 위치에 갈 수 없습니다(예: 야자수 오른쪽 → 라군 왼쪽 → 야자수 위). 보드가 좁아 맨 윗줄에 붙은 블록이
  쉽게 비켜나지 못하므로, 다른 블록을 먼저 치우는 순서가 중요하고, 블록이 제거되면 새 길이 열립니다.

**중력 규칙 A (`"collect": "drain"` 또는 생략) — 현재 사용하는 스테이지 없음, 비교용으로 유지**

- 시작할 때는 그림이 빈칸 없이 꽉 차 있어서 움직이지 않습니다.
- 맨 윗줄에 있는 블록 셀 중 위가 노출된 셀이 수집구입니다. 수집구 바로 위 픽셀에 **같은 색 모래가 직접 닿아야** 수집이 시작됩니다.
- 닿은 모래와 상하좌우로 이어진 같은 색 덩어리가, 연결된 길을 따라 한 알씩 수집구로 흘러 들어옵니다(먼 쪽부터 비워짐).
  다른 색은 통과하지 않고, 대각선 연결은 인정하지 않습니다.
- 모래가 빠진 자리로 위쪽과 주변 모래가 떨어지거나 대각선 아래로 흘러내려 그림이 실제로 무너집니다. 다른 색도 똑같이 무너집니다.
- 블록이 없는 맨 윗줄 칸은 단단한 바닥이라, 모래가 보드로 떨어지지 않습니다.
  다른 색 모래가 수집구 위에 쌓이면 그 자리는 막히므로, 그 색 블록을 가져와야 합니다.
- 수집 속도와 낙하 속도는 `data/game_config.json`의 `gravity` 항목에서 조절합니다.

**나머지 스테이지 — 통로 규칙 (기본값)**

- 블록 셀의 윗면이 풍경 맨 아래 줄 픽셀에 닿아야 합니다. 대각선 접촉은 인정하지 않습니다.
- 수집은 닿은 지점에서 시작해, 같은 색 모래와 이미 비워진 자리(통로)를 따라 가까운 곳부터 순서대로 퍼집니다.
- 다른 색 모래는 통과하지 못합니다. 수집되지 않은 모래는 움직이지 않습니다.

### 여행 화면 (홈 · 세계 지도 · 대륙 · 여행지 · 앨범)

- **홈:** 지금 여행 중인 여행지 엽서와 진행 상태, **이어서 여행하기**(다음에 열린 스테이지), 세계 지도, 여행 앨범, 설정.
- **세계 지도:** 대륙별 진행 상태(방문 스탬프 수)와 무료 여행지만 표시합니다. 대륙 배지나 카드를 눌러 들어갑니다.
- **대륙:** 그 대륙의 모든 여행지(확정 목록 100곳 중) 지도와 엽서 목록. 전체 / 무료 / 플레이 가능 필터.
- **여행지 시트:** 큰 엽서, 스테이지 3개(완료 · 출발 · 잠김 · 준비 중 · 여행 패스).
  - 스테이지는 여행지 안에서 1 → 2 → 3 순서로 열립니다. 예전에 클리어한 스테이지는 그대로 열려 있습니다.
  - 무료 여행지는 자유롭게 고를 수 있습니다.
  - 프리미엄 여행지는 여행 패스가 필요합니다. 결제는 아직 없고 안내 화면만 있습니다.
- **준비 중:** 여행지 목록(`data/travel_catalog.json`)에만 있고 그림·스테이지 데이터가 없는 곳은 무료/프리미엄과 관계없이 플레이할 수 없습니다.
  플레이 가능 여부는 `data/stages.json`의 `<여행지>_<nn>` 스테이지와 그 그림 파일이 실제로 있는지로 판단합니다.
- **여행 앨범:** 대륙 탭 → 여행지마다 엽서 3장(스테이지 클리어 시 획득), 3장 모두 모으면 방문 완료 스탬프.
  엽서 그림은 화면 근처에 올 때만 작은 썸네일(256px)로 만들어 쓰고(최대 48장 캐시), 원본은 크게 볼 때 1장만 불러옵니다.

### 스테이지별 풍경 (선택)

`data/stages.json`의 스테이지에 `landscape`를 넣으면 그 스테이지만 다른 그림을 씁니다. 없으면 여행지 그림을 그대로 씁니다(기존 9개 스테이지).

```json
"landscape": { "puzzle": {"64": "paris_s2_puzzle64.png", "128": "paris_s2_puzzle128.png"},
               "album": "paris_s2_album.png", "palette": [ {"key": "sky", "name_ko": "하늘", "color": "#bfe2ef"} ] }
```

경로는 `destinations.json`의 `asset_dir` 기준(또는 `res://`)입니다. `palette`를 생략하면 여행지 팔레트를 씁니다.

### 진행 저장

- 스테이지 클리어 기록(= 엽서), 여행지 첫 클리어 기록(기존 앨범 기록), 마지막으로 플레이한 스테이지(`last_played`)가 `user://save.json`에 저장되며, 재실행해도 유지됩니다.
  예전 세이브도 그대로 읽힙니다. 구매 권한은 세이브에 저장하지 않습니다(`App.entitlements`, 스토어 연동 시 채움).
- Windows 기준 경로: `%APPDATA%\Godot\app_userdata\Sandy Voyage\save.json`
- 처음부터 다시 하려면 이 파일을 지우세요.
- 자동 플레이 도구는 별도 파일(`autoplay_save.json`)을 써서 플레이어 기록을 건드리지 않습니다.

## 구조

```
data/travel_catalog.json 확정 여행지 100곳: 대륙, 국가, 대표 풍경, 무료/프리미엄, 지도 좌표(대략값)
data/destinations.json   그림이 있는 여행지의 이미지 경로, 색 팔레트 (아트 교체는 여기서)
data/stages.json         스테이지 배치 (보드, 벽, 블록, capacity "auto")
data/game_config.json    수집 속도, 입자 수 제한, 기본 해상도(128)
data/sounds.json         사운드 이벤트 → 오디오 파일 (비어 있으면 무음)
scripts/sand/            SandMap: PNG 픽셀 → 색상 ID 모래 데이터, SandSim: 낙하 모래(활성 구역만 계산)
scripts/core/            보드, 블록, 수집(통로: SandCollector, 중력 A: GravityDrain, 중력 B-2: SuctionDrain), 게임 상태, 로더, 검증기, 저장
scripts/ui/              화면과 렌더링 (게임 규칙 없음). 모래는 R8 텍스처 + 팔레트 셰이더로 그림
scripts/autoload/        App(저장·설정·썸네일·구매 권한 자리), Sfx(사운드 이벤트)
assets/ui/               세계 지도 육지 마스크 (tools/make_world_mask.py, Natural Earth 퍼블릭 도메인)
scripts/debug/autoplay.gd  실제 UI에 드래그·클릭을 주입해 자동 플레이
tests/                   헤드리스 테스트, 레벨 검증기, 벤치마크
```

## 테스트 명령

```
G=path/to/Godot_v4.7.2-stable_win64_console.exe
$G --headless --path . --import                                   # 에셋/클래스 추가 후
$G --headless --path . -s res://tests/test_sand_map.gd            # PNG → 모래 데이터
$G --headless --path . -s res://tests/test_gameplay.gd            # 통로 규칙, 이동, 저장, 검증기
$G --headless --path . -s res://tests/test_travel.gd              # 여행지 목록, 해금, 스테이지별 풍경, 세이브 호환
$G --headless --path . -s res://tests/test_gravity.gd             # 중력 규칙 A (하와이 1을 A로 만들어 끝까지 플레이)
$G --headless --path . -s res://tests/test_suction.gd             # 중력 B-2 흡입, 하와이 1 끝까지 플레이
$G --headless --path . -s res://tests/validate_levels.gd          # 모든 스테이지, 128과 64
$G --headless --path . -s res://tests/validate_levels.gd -- --stage=hawaii_01 --res=128 --plan
$G --headless --path . -s res://tests/bench_collect.gd            # 로직 비용 128 vs 64 (B-2는 탐색 시간 포함)
$G --path . -- --autoplay=hawaii_01 --res=128 --shots=<dir>       # UI 자동 플레이 + 스크린샷
$G --path . -- --autoplay=all --shots=<dir>                       # 9개 스테이지를 홈 → 여행지 시트 UI로 순서대로
$G --path . -- --autoplay=ui-shots --shots=<dir>                  # 여행 화면 전체 스크린샷 (별도 세이브 파일)
$G --path . -- --autoplay=verify-save                             # 새 프로세스에서 저장 유지 확인
```

`validate_levels.gd`가 보고하는 드래그 횟수는 **최단 경로가 아닙니다.**
중력 스테이지는 단순한 자동 정책(한 알이라도 닿는 가장 가까운 배치로 이동)으로 실제 tick을 돌려 확인하므로, 사람의 플레이보다 이동이 훨씬 많게 나옵니다.
가장 가까운 수집 위치를 반복해서 찾는 탐욕적(greedy) 경로라서, 클리어 가능성의 증거로만 쓰고 난이도 지표로는 쓰지 않습니다.
